# ПРОМПТ ЭТАПА 9 — Интеграция, UX/UI, адаптивность и карта

## 1. РОЛЬ
Ты — продуктовый UI-инженер. Твоя задача — довести функциональность до цельного, быстрого и доступного интерфейса, не меняя доменную логику.

## 2. КОНТЕКСТ
Все функции реализованы (этапы 1–8). Теперь важны последовательность, состояния, доступность, мобильный опыт и карта.

## 3. ТЕКУЩАЯ АРХИТЕКТУРА
Next.js App Router, Tailwind, компоненты `components/ui` и `components/knowledge`, API v1.

## 4. РЕЗУЛЬТАТЫ ЭТАПОВ 0–8
Полный функционал на реальных данных; админка; граф; поиск.

## 5. ЦЕЛЬ
Единый визуальный язык, отсутствие «сырых» мест, адаптивность 380–1440, a11y без critical, карта, SEO, предсказуемые состояния загрузки/ошибок.

## 6. ТЕХНИЧЕСКОЕ ЗАДАНИЕ
1. Дизайн-токены из `05-ui-ux.md` — единственный источник цветов/типографики; никаких случайных hex в компонентах.
2. Провести аудит всех страниц по чек-листу: заголовок, хлебные крошки, пустые состояния, скелетоны, ошибки, мобильный вид.
3. Карта `/map`: MapLibre, кластеры, попапы, фильтр по стране, lazy-load, fallback-список при недоступных тайлах, атрибуция OSM.
4. Доступность: контраст ≥ 4.5:1, focus-visible, клавиатура (меню, фильтры, граф, формы), `prefers-reduced-motion`, семантика, `aria-live` для результатов поиска.
5. Производительность: LCP < 2.5 с, CLS < 0.1, INP < 200 мс (локальный прод-билд); изображения — `next/image` при наличии; шрифты — `next/font`, `display=swap`.
6. SEO: метаданные на всех страницах, canonical, sitemap из published, robots (закрыть `/admin`, `/login`), Open Graph без фейковых изображений.
7. Единые тексты: ошибки, пустые состояния, подсказки; без техножаргона в UI.
8. Полировка графа: легенда, подписи, читаемость при 200 узлах, мобильная шторка.
9. Скелетоны и `loading.tsx` для всех сегментов; `error.tsx` с `requestId`.
10. Финальный визуальный проход: отступы, выравнивания, плотность таблиц, состояния hover/active/disabled.

## 7. ЗАДАЧИ
1. Аудит-таблица «страница → проблемы → исправлено» в PR.
2. Набор компонентов-состояний (loading/empty/error) и их применение везде.
3. Карта + fallback.
4. a11y-прогон axe по 10 страницам; исправления.
5. Lighthouse (mobile) для главной, каталога, карточки, графа; отчёт.
6. Обновление `docs/UI.md` (если появились отклонения).

## 8. ТЕХНОЛОГИЧЕСКИЕ ОГРАНИЧЕНИЯ
- Не менять API/схему данных.
- Не добавлять анимационные библиотеки.
- Не вводить вторую UI-систему.
- Карта не должна быть обязательной для навигации.

## 9. КАЧЕСТВО
- Нет «прыжков» layout при загрузке.
- Нет обрезанных текстов без тултипа/переноса.
- Все интерактивные элементы имеют состояния и доступное имя.
- Единый тон текстов (ты/вы — выбрать и соблюдать; рекомендация: «вы»).

## 10. БЕЗОПАСНОСТЬ
- CSP совместима с картой/шрифтами (без ослабления до `unsafe-eval`).
- Внешние ресурсы — только утверждённые домены.
- Никаких трекеров/аналитики.
