## 6. ТЕХНИЧЕСКОЕ ЗАДАНИЕ (аудит)

### A. Запуск с нуля
1. Клон в чистый каталог, `.env` из примера, `docker compose up -d db`, миграции, сид, dev-запуск.
2. Зафиксировать все отклонения от README (каждая команда — факт).
3. Проверить `docker compose -f docker-compose.prod.yml up` (если предусмотрен).

### B. Архитектура и код
1. Слои controller/service/repository соблюдены? Найти нарушения (SQL в контроллере, логика в компоненте UI).
2. Нет дублирования (две реализации related, две формы, два маппера).
3. Нет мёртвого кода, `TODO/FIXME`, `any`, заглушек в пользовательских путях.
4. Зависимости: обоснованы, не дублируют друг друга, нет заброшенных/уязвимых (`pnpm audit` — с оценкой).
5. Миграции воспроизводимы; `migrate reset` на чистой БД.

### C. Модель знаний (главное)
1. Все ли классы/связи из `04-knowledge-model.md` реализованы?
2. Работают ли R1–R6 и совпадают ли с документацией?
3. `knowledge_edge` валидируется (domain/range, дубли, self-loop)?
4. Провенанс: есть ли published-объекты без источника? Показывается ли дата проверки?
5. Inferred-факты не хранятся как истина и помечены?
6. Поиск: FTS+trigram+синонимы, фасеты, eval-набор; нет ли «поиска по массиву».
7. Граф: лимиты, циклы, восстановление из URL, соответствие «связано с».
8. Обработка NULL/неизвестности: нет подстановки нулей/фейков.

### D. Функциональная приёмка
Пройти все модули A–J по `02-functional-spec.md` и отметить «работает / частично / нет» с доказательством (скриншот, curl, тест). Особое внимание:
- фильтры комбинируются и живут в URL;
- карточки показывают источники;
- админка: публикация без источника запрещена; RBAC;
- поиск: «тигр» → вид + зоопарки; опечатки → suggestions;
- граф: переходы, панель узла;
- карта: fallback.

### E. Безопасность
1. Матрица прав: 401/403 на каждом защищённом маршруте.
2. Cookie-флаги, Argon2id, rate limit, CSRF/Origin, CSP.
3. Секреты: `git grep` + history (если был инцидент — отметить), `.env` не в репозитории.
4. Ошибки не раскрывают стектрейсы в prod.
5. Инъекции: проверить параметризацию, whitelist сортировок.

### F. Тесты и качество
1. `pnpm test`, `test:api`, `test:e2e` — полный прогон; зафиксировать пропуски.
2. Нет `.skip`/`.only`/пустых assert.
3. E2E 8 сценариев на двух вьюпортах.
4. axe: 0 critical/serious.
5. Покрытие сервисов ≥ 80%.
6. flaky: 3 прогона e2e.

### G. Производительность
1. p95 поиска/каталогов/графа; LCP/CLS.
2. `EXPLAIN` ключевых запросов: нет ли seq scan на больших таблицах.
3. Нет N+1 на карточках (логи запросов).

### H. Данные
1. Объёмы из этапа 8 достигнуты.
2. Нет вымышленных сущностей/фактов; 10% выборка проверена.
3. Источники: URL рабочие (выборочно 20), `accessedAt` заполнен.
4. Дубли/битые slug/циклы таксонов — нет (`data:check`).

### I. Документация
1. README точен; команды работают.
2. `docs/DEMO.md` проходит.
3. Документы не противоречат коду (doc-drift список).
4. CHANGELOG и тег.
