# ПРОМПТ ЭТАПА 8 — Наполнение базы реальными данными

## 1. РОЛЬ
Ты — data curator/инженер данных. Ты не генерируешь факты. Ты собираешь, нормализуешь, атрибутируешь и проверяешь сведения из официальных источников.

## 2. КОНТЕКСТ
EuroZoo Atlas. «Нет источника — нет факта». Данные: реальные европейские зоопарки, виды, организации, программы. Никаких вымышленных сущностей.

## 3. ТЕКУЩАЯ АРХИТЕКТУРА
Сид-фреймворк (этап 3), админка (этап 7), `source`/`entity_source`, `data:check`, `data:stale`, `data:verify`.

## 4. РЕЗУЛЬТАТЫ ЭТАПОВ 0–7
Все функции работают на тестовых данных; публикация требует источник; провенанс отображается.

## 5. ЦЕЛЬ
База, достаточная для полноценной демонстрации: ≥ 30 зоопарков, ≥ 12 стран, ≥ 25 городов, ≥ 60 видов, ≥ 15 программ, ≥ 10 организаций, ≥ 8 исследований, ≥ 20 образовательных программ, ≥ 40 рёбер; 100% published-объектов с источниками.

## 6. ТЕХНИЧЕСКОЕ ЗАДАНИЕ
1. Источники (приоритет): официальные сайты зоопарков; EAZA; IUCN Red List; GBIF; национальные ассоциации; официальные страницы программ; научные публикации (DOI). Запрещены: Википедия как единственный источник ключевого факта, блоги, форумы, ИИ-сгенерированные тексты.
2. Формат: JSON по сущностям в `database/seeds/`; каждое утверждение снабжается `sourceRefs: [sourceId]`; для ключевых полей — `verifiedAt`.
3. Поля источника: `type`, `title`, `url` (рабочий, проверен), `publisher`, `publishedAt` (если есть), `accessedAt` (обязательно), `license`, `reliability`.
4. Правила заполнения: `NULL` вместо догадок; `year` без даты; никаких «примерно 1900». Названия — как в официальном источнике + локализация, если подтверждена.
5. Валидация: `pnpm data:verify` — проверяет URL-формат и домен из allowlist, наличие источника у published, отсутствие дублей (slug/scientific_name/iso2), согласованность годов/координат, битые связи.
6. Отчёт `docs/DATA-REPORT.md`: покрытие по сущностям, распределение по странам/статусам, список источников, доля проверенных вручную (≥ 10% выборка), известные пробелы.
7. Импорт: только через сид-загрузчик (идемпотентный) или админку; никаких ручных SQL-вставок в demo-БД без миграции/сида.

## 7. ЗАДАЧИ
1. Сформировать список зоопарков (30+) по странам; для каждого: город, координаты, год основания, сайт, 1–2 факта с источником.
2. Таксономия: 60+ видов; линия до семейства минимум; IUCN для большинства; ареалы.
3. Программы: 15+ (EEP/ESB/studbook), оператор-организация, целевые виды, участники-зоопарки (только подтверждённые).
4. Организации: 10+ (EAZA, WAZA, национальные ассоциации и др.).
5. Связи: `zoo_species` (≥ 150), `zoo_program` (≥ 60), `knowledge_edge` (≥ 40), исследования/образование (≥ 8/20).
6. Источники: ≥ 80 записей; у каждого published-объекта ≥ 1.
7. Проверка: `data:check`, `data:verify`, выборочная ручная сверка 10% фактов (зафиксировать в отчёте).
8. Скриншоты 5 карточек с видимым провенансом.

## 8. ТЕХНОЛОГИЧЕСКИЕ ОГРАНИЧЕНИЯ
- Никаких внешних API в runtime; сбор — офлайн, в файлы.
- Никакой генерации текстов «для объёма». Описание — краткое, по источнику.
- Не добавлять вид в зоопарк без подтверждения (официальный список животных/годовой отчёт).
- Не использовать источники с нерабочими URL.

## 9. КАЧЕСТВО
- Единый стиль описаний: 1–3 предложения, факты, без маркетинга.
- Даты в ISO; координаты — 6 знаков; названия видов — с автором и годом, где доступно.
- Все slug — латиница, kebab-case, стабильные.

## 10. БЕЗОПАСНОСТЬ/ПРАВО
- Соблюдать лицензии источников; не копировать большие фрагменты текста; атрибуция обязательна.
- Не публиковать персональные данные сотрудников.
- Не использовать изображения без лицензии; медиа — опционально.

## 11. GITHUB
Ветка `stage/8-real-data`; PR с `DATA-REPORT.md` и списком источников; сид-файлы в репозитории; CI прогоняет `data:check` и `data:verify`.

## 12. PRE-FLIGHT
Проверить: этап 7 принят; пустая БД разворачивается; allowlist доменов согласован; нет конфликтов slug с тестовыми данными.

## 13. СОВМЕСТИМОСТЬ
Данные не должны ломать тесты этапов 3–7: обновить фикстуры, если они зависели от количества строк; прогнать весь e2e.

## 14. ТЕСТЫ
- `data:check` / `data:verify` в CI — обязательны.
- Повторный сид идемпотентен.
- Выборочный тест: 10 случайных published-объектов имеют источник с `verifiedAt`.
- Проверка отсутствия вымышленных доменов/битых URL (HEAD/GET).
- E2E smoke на реальных данных (главная, 3 карточки, поиск).

## 15. КРИТЕРИИ ПРИЁМКИ
- [ ] Достигнуты минимальные объёмы (см. цель).
- [ ] 100% published-объектов имеют источник.
- [ ] Нет дублей и вымышленных сущностей.
- [ ] `data:check`/`data:verify` зелёные.
- [ ] `DATA-REPORT.md` содержит покрытие и пробелы.
- [ ] 10% фактов проверены вручную (список в отчёте).
- [ ] Отчёт по шаблону.

## 16. ОТЧЁТ
По шаблону + `DATA-REPORT.md` + 5 скриншотов + список источников + перечень пробелов.

## 17. ЗАПРЕЩЕНО
- Выдумывать зоопарки, виды, программы, годы, координаты, источники.
- Заполнять поля «по смыслу», если источник не подтверждает.
- Использовать ИИ-тексты как источник.
- Массово копировать контент сайтов.
- Оставлять published-объекты без источника «временно».
