# ПРОМПТ ЭТАПА 6 — Логические связи и визуализация знаний

## 1. РОЛЬ
Ты — инженер графовых представлений. Ты не создаёшь вторую базу данных: ты проецируешь существующие связи в понятный интерфейс.

## 2. КОНТЕКСТ
Связи хранятся в FK + `knowledge_edge` (реестр `predicate`). Вывод R1–R6 — SQL-представления. UI — React Flow + ELK.

## 3. ТЕКУЩАЯ АРХИТЕКТУРА
Модули api этапа 3; поиск/«связано с» этапа 5; карточки этапа 4.

## 4. РЕЗУЛЬТАТЫ ЭТАПОВ 0–5
Данные, API, каталоги, поиск; провенанс и inferred-бейджи.

## 5. ЦЕЛЬ
Пользователь видит и исследует граф знаний: серверный подграф, интерактивная сцена, панель узла, фильтры, восстановление состояния из URL, честные лимиты.

## 6. ТЕХНИЧЕСКОЕ ЗАДАНИЕ
1. `GET /graph?seed=<type>:<id>&depth=1..3&types=a,b&predicates=X,Y&inferred=true&limit=200` → `{nodes, edges, truncated, stats}`.
2. Обход: рекурсивный CTE BFS, старт от seed; рёбра = структурные (FK) + `knowledge_edge` + (опционально) inferred-представления; белый список предикатов и типов; защита от циклов (`visited`), лимит узлов 200 / рёбер 400; `truncated=true` при превышении.
3. Проекция узла: `{type, id, label, subtitle, url, degree, inferred?}`; ребра: `{src, dst, predicate, label_ru, confidence, inferred}`.
4. UI `/graph`: canvas, панель фильтров, легенда типов, панель узла (краткое описание + «Открыть карточку» + «Развернуть»), кнопки: сброс, экспорт PNG, копировать ссылку.
5. Layout: ELK layered (направление сверху вниз); при > 120 узлах — упрощённые подписи; hover подсвечивает инцидентные рёбра.
6. URL-состояние: `seed`, `depth`, `types`, `predicates`, `inferred`; при загрузке — восстановление.
7. Производительность: ≤ 1.5 с на рендер 200 узлов; запрос графа ≤ 800 мс.
8. Доступность: клавиатурная навигация по узлам (Tab/Enter), `aria-label` на canvas-контейнере, текстовый список связей как альтернатива («Список связей» вкладкой).

## 7. ЗАДАЧИ
1. `GraphService`: traversal, projection, валидация seed/лимитов, ошибки (404 seed, 400 параметры).
2. Кэш: 60 с на подграф (ключ = параметры), инвалидация при мутациях (этап 7).
3. Компоненты: `GraphCanvas`, `GraphFilters`, `GraphLegend`, `NodePanel`, `RelationList`.
4. Страница `/graph` + кнопка «В графе» на карточках.
5. Тесты: SQL traversal (цикл, дубли, глубина), API, e2e сценарий, perf.
6. Документация: `docs/GRAPH.md` — предикаты, лимиты, примеры ответов.

## 8. ТЕХНОЛОГИЧЕСКИЕ ОГРАНИЧЕНИЯ
- Никакой второй БД/графового движка.
- Никаких клиентских запросов «по одному узлу» при первичной загрузке (N+1 запрещён).
- Рендер не должен блокировать основной поток (> 50 мс задач — в `requestIdleCallback`).
- Никаких анимаций сверх подсветки/переходов.

## 9. КАЧЕСТВО
- Граф детерминирован для одинаковых параметров (стабильный layout-порядок).
- Нет висячих рёбер (ребро всегда ссылается на существующий узел ответа).
- Inferred-рёбра визуально отличимы (dashed) и объяснены в легенде.
- Список связей — полноценная альтернатива (доступность + отладка).

## 10. БЕЗОПАСНОСТЬ
- Валидация `seed` (тип из enum, id — uuid), depth 1..3, limit ≤ 200.
- Нет раскрытия draft-сущностей неавторизованным (проверка статуса при проекции).
- Rate limit 20 запросов/мин/IP на `/graph`.

«Связано с» (этап 5) и граф используют один сервис проекции; не допускается две реализации соседей.

## 14. ТЕСТЫ
- SQL: seed с 3 уровнями, цикл A→B→A, дубликаты, отсутствующий seed.
- API: параметры (невалидный тип, depth=0/4, limit=500), 404, truncated.
- E2E: зоопарк → «В графе» → depth 2 → клик узла → карточка; восстановление из URL.
- A11y: сцена доступна, список связей доступен.
- Perf: 200 узлов < 1.5 с.
