# ПРОМПТ ЭТАПА 7 — Административная панель и безопасность

## 1. РОЛЬ
Ты — full-stack инженер, отвечающий за безопасное редактирование знаний: формы, права, публикация, провенанс, аудит.

## 2. КОНТЕКСТ
EuroZoo Atlas. Роли: VIEWER/EDITOR/ADMIN. Сессии — серверные cookie + Argon2id. Публикация требует источника.

## 3. ТЕКУЩАЯ АРХИТЕКТУРА
Доменные сервисы (этап 3), карточки (этап 4), поиск (этап 5), граф (этап 6). `entity_source`, `knowledge_revision`, `knowledge_edge` существуют.

## 4. РЕЗУЛЬТАТЫ ЭТАПОВ 0–6
Публичная часть завершена; API стабилен; есть тестовая БД и сид.

## 5. ЦЕЛЬ
Админ может управлять контентом, связями, источниками и пользователями; права проверяются на сервере; каждая мутация аудируется; публикация невозможна без источника.

## 6. ТЕХНИЧЕСКОЕ ЗАДАНИЕ
1. Auth: `POST /auth/login` (email+password), `POST /auth/logout`, `GET /auth/me`; сессия 7 дней, sliding, httpOnly/SameSite=Lax/Secure(prod); Argon2id; `BOOTSTRAP_ADMIN_*` только для сида.
2. RBAC: guard на роли; матрица из `02-functional-spec.md`; 401 vs 403 различаются; нельзя деактивировать последнего админа.
3. CRUD (api + UI): zoos, taxa/species, countries/regions/cities, programs, organizations, research, education, facilities, events, sources, synonyms, users.
4. Формы: zod на клиенте и сервере; inline-ошибки; `updated_at` для оптимистической блокировки (409 с diff); «грязный» guard; сохранение введённого при 422.
5. Связи: M:N-редактор (поиск, добавление, удаление), `zoo_species` (counts/years/breeding/enclosure), `zoo_program` (role/years), `knowledge_edge` (предикат из реестра, проверка domain/range, confidence, source).
6. Публикация: `draft → review → published`; блокировка при отсутствии источника или `verified_at` ключевых полей; кнопка «Проверено» проставляет `verified_at` и обновляет `retrieved_at`.
7. Источники: CRUD, привязка к сущности/полю, `reliability`, `confidence`, `status`; запрет удаления источника при ссылках (409).
8. Ревизии: каждая мутация пишет `knowledge_revision` (actor, action, diff); страница `/admin/revisions` с фильтрами.
9. Дашборд `/admin`: счётчики, объекты без источников, стейл, последние изменения, ошибки `data:check`.
10. Инвалидация: после мутации — refresh поискового индекса (debounce 2 с) + инвалидация кэша графа/списков.
11. Безопасность: rate limit логина (5/мин/IP, 10/час/аккаунт), блокировка 15 мин после 10 неудач, CSRF-проверка Origin для не-GET, CSP без `unsafe-inline` в prod.

## 7. ЗАДАЧИ
1. Модуль `auth` + guard'ы + декораторы.
2. Модуль `admin` с контроллерами по ресурсам и общими helper'ами (pagination, conflict, validation).
3. UI: layout с проверкой сессии, списки, формы, M:N-редакторы, публикация, ревизии, пользователи.
4. Тесты прав (каждый маршрут × каждая роль), тесты публикации, конфликтов, аудита.
5. Документация: `docs/ADMIN.md` (роли, публикация, правила источников).

## 8. ТЕХНОЛОГИЧЕСКИЕ ОГРАНИЧЕНИЯ
- Никаких JWT в localStorage; только cookie.
- Никаких «скрытых» кнопок как единственной защиты — сервер проверяет всегда.
- Никаких массовых `updateMany` из UI без явной операции и подтверждения.

## 9. КАЧЕСТВО
- Один `entity-form`-каркас, конфигурируемый по схеме; не 15 копий форм.
- Ошибки API маппятся на поля, а не в общий toast.
- Все мутации — транзакции; diff ревизии — осмысленный (только изменённые поля).

## 10. БЕЗОПАСНОСТЬ
- Пароли: ≥ 12 символов, проверка на утечки не требуется, но запрещены очевидные (`password`, email).
- Хеширование Argon2id (memory 19456 KiB, time 2, parallelism 1) — параметры в одном месте.
- Cookie не содержат данных пользователя; токен — случайные 32+ байта, в БД — хеш.
- Ошибки логина не раскрывают, существует ли аккаунт.
- Аудит-лог не содержит паролей/токенов.
- OWASP-проверка: A01 (доступ), A02 (крипто), A03 (инъекции), A05 (конфиг), A07 (аутентификация), A08 (целостность), A09 (логи).

## 13. СОВМЕСТИМОСТЬ
Публичные DTO не должны получить админ-поля. Мутации не ломают read-API; публикация влияет на видимость, но не на схему.

## 14. ТЕСТЫ
- API: 401 без сессии, 403 для роли, 200 для разрешённой; публикация без источника → 422; конфликт → 409; удаление источника со ссылками → 409.
- Auth: неверный пароль/несуществующий email — одинаковый ответ; rate limit; истечение сессии; logout инвалидирует.
- Ревизии: каждая мутация создаёт запись с diff.
- E2E: логин → создание зоопарка → публикация запрещена → источник → публикация → видно на сайте.
- A11y форм: labels, ошибки, фокус.
