# ПРОМПТ ЭТАПА 4 — Каталоги и карточки объектов

## 1. РОЛЬ
Ты — frontend/full-stack инженер, отвечающий за исследовательский UX: каталоги, карточки, фильтры, навигацию по знаниям.

## 2. КОНТЕКСТ
EuroZoo Atlas. Web — Next.js 15 App Router, RSC по умолчанию; данные — из `apps/api` по контрактам этапа 1; дизайн — `docs/spec/05-ui-ux.md`.

## 3. ТЕКУЩАЯ АРХИТЕКТУРА
Read-API этапа 3; базовый layout и компоненты этапа 2; схема и DTO утверждены.

## 4. РЕЗУЛЬТАТЫ ЭТАПОВ 0–3
Аудит, архитектура, фундамент, ядро данных и read-API работают; сид даёт валидные данные.

## 5. ЦЕЛЬ
Все публичные каталоги и карточки открываются, фильтры/сортировки/пагинация работают через URL, каждый факт показывает провенанс, переходы между знаниями ведут к связанным объектам.

## 6. ТЕХНИЧЕСКОЕ ЗАДАНИЕ
Маршруты: `/zoos`, `/zoos/[slug]`, `/species`, `/species/[slug]`, `/taxonomy`, `/taxonomy/[rank]/[slug]`, `/countries`, `/countries/[slug]`, `/cities/[slug]`, `/programs`, `/programs/[slug]`, `/organizations`, `/organizations/[slug]`, `/research`, `/research/[slug]`, `/sources`.

Для каждого:
1. Server Component; `generateMetadata` (title/description/OG/canonical).
2. Каталог: фильтры (URL), сортировка, пагинация, empty state, скелеты при навигации.
3. Карточка: заголовок с контекстом, бейджи (статус, IUCN), секции, «связано с», «похожие», источники.
4. Провенанс: компонент `SourceBadge` (тултип: источник, дата проверки, достоверность); для inferred — бейдж «выведено» + пояснение.
5. Таблица видов в карточке зоопарка: вид, IUCN, количество, разведение, ссылка.
6. Таксономическая линия: хлебные крошки вверх до корня, кликабельны; дети таксона — список.
7. 404 и error boundary для каждого динамического сегмента.
8. Мобильная адаптация по `05-ui-ux.md` (фильтры в шторке, таблицы со скроллом).
9. Метрики: не более 6 запросов на карточку; `Promise.all` для независимых блоков; `Suspense` для тяжёлых секций.

## 7. ЗАДАЧИ
1. `lib/api-client.ts` с типизированными вызовами и обработкой ошибок.
2. Компоненты: `EntityCard`, `FilterPanel`, `DataTable`, `IucnBadge`, `SourceBadge`, `LineageTree`, `EmptyState`, `Breadcrumbs`.
3. Страницы списков и карточек (по списку выше).
4. URL-состояние: чтение/запись query-параметров, сброс фильтров, канонические URL.
5. Обработка отсутствующих данных: «нет данных», без нулей.
6. SEO: `sitemap.ts`, `robots.ts`, JSON-LD (`Organization` для зоопарка) без ложных полей.
7. Тесты: RTL для компонентов, Playwright для 4 сценариев.

## 8. ТЕХНОЛОГИЧЕСКИЕ ОГРАНИЧЕНИЯ
- Не добавлять клиентский state-менеджер; TanStack Query только там, где нужен интерактив (фильтры можно серверно).
- Никаких тяжёлых UI-библиотек; только утверждённые компоненты.
- Никаких изображений-заглушек «из интернета»; если нет медиа — не показывать блок.
- Не хардкодить данные в компонентах.

## 9. КАЧЕСТВО
- Компоненты без бизнес-логики; форматирование — в `lib/formatters`.
- Доступность: семантические заголовки, `caption` у таблиц, focus, aria для фильтров.
- Нет layout shift: скелеты с фиксированными размерами.
- Тексты интерфейса — русские, единый тон, без англицизмов там, где есть термин.

## 10. БЕЗОПАСНОСТЬ
- Внешние ссылки: `rel="noopener noreferrer"`, `target="_blank"` только осознанно.
- Экранирование любых данных от пользователя; `dangerouslySetInnerHTML` запрещён.
- Не логировать query с потенциальными персональными данными.

## 11. GITHUB

## 12. PRE-FLIGHT

## 13. СОВМЕСТИМОСТЬ
Не менять API-контракты этапа 3 без `shared-change`. Все добавленные поля — опциональные и обратно совместимые.

## 14. ТЕСТЫ
- RTL: `SourceBadge` (тултип, дата), `FilterPanel` (сброс), `DataTable` (пусто/сортировка), `LineageTree`.
- Playwright: каталог зоопарков с фильтрами и reload; карточка вида; переход по таксономии; 404.
- A11y: axe на 4 страницах — 0 critical.
- Snapshot — только для стабильных частей (не для данных).

- [ ] Нет N+1: ≤ 6 запросов на карточку (проверка логом).
- [ ] Мобильный вид 390×844 без горизонтального скролла.
- [ ] 404/error работают.
- [ ] Отчёт по шаблону + скриншоты.
