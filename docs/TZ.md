# Техническое задание (ЭТАП 0)

Проект: **EuroZoo Atlas** — база знаний о европейских зоопарках.
Основание: `docs/spec/01-concept-and-domain.md` … `06-delivery-plan.md`.
Статус: на согласовании (ЭТАП 0).

## 1. Цель

Создать веб-систему, которая хранит знания о европейских зоопарках как связную модель (зоопарк ↔ география ↔ виды ↔ таксономия ↔ программы сохранения ↔ организации ↔ источники), поддерживает поиск и исследование связей и показывает происхождение каждого факта.

## 2. Пользователи и роли

| Роль | Задачи |
|---|---|
| Гость (VIEWER) | искать, читать карточки, исследовать граф |
| Редактор (EDITOR) | создавать/редактировать контент и связи, добавлять источники, публиковать после проверки |
| Администратор (ADMIN) | управлять пользователями, удалять сущности, публиковать, следить за качеством данных |

## 3. Границы

**В scope v1:** каталоги зоопарков/видов/стран/городов/программ/организаций/исследований; карточки с провенансом; полнотекстовый поиск с фасетами и синонимами; граф связей с лимитами; админ-панель с RBAC и ревизиями; карта; 30+ зоопарков и 60+ видов реальных данных; тесты; документация; Docker-развёртывание.

**Вне scope v1:** мобильное приложение, OAuth/SSO, платежи, отзывы, реалтайм-интеграции, Elasticsearch/Neo4j/Redis/pgvector, Kubernetes, полноценный OWL-ризонер, мультиязычный UI.

## 4. Функциональные требования (по модулям)

| Модуль | Требование | Приёмка |
|---|---|---|
| A. Главная | реальные счётчики, быстрые входы, недавно обновлённое, популярные связи | цифры совпадают с API, LCP < 2.5 с |
| B. Зоопарки | каталог с фильтрами в URL, карточка с 9 секциями и провенансом | фильтры комбинируются, ≤ 6 запросов на карточку |
| C. Виды | каталог, карточка, линия таксонов до корня, IUCN, где содержится | фильтр по семейству включает потомков |
| D. География | страны/города/карта с fallback | агрегаты совпадают с каталогом |
| E. Программы | каталог, карточка, участники и целевые виды | программа без видов не публикуется |
| F. Поиск | FTS + trigram + синонимы, фасеты, связанные объекты | 20/20 eval-запросов, p95 ≤ 400 мс |
| G. Граф | подграф от сущности, фильтры, панель узла, URL-состояние | лимиты 200/400, циклы безопасны |
| H. Админка | CRUD, связи, публикация, пользователи, ревизии | матрица прав тестами, 422 без источника |
| I. Источники | провенанс, доверие, стейл, методика | published без источника невозможен |
| J. Безопасность | сессии, Argon2id, RBAC, rate limit, CSRF, CSP | 401/403 на каждом защищённом маршруте |

Детализация — `docs/spec/02-functional-spec.md`.

## 5. Нефункциональные требования

| Категория | Требование |
|---|---|
| Производительность | p95: каталоги ≤ 300 мс, поиск ≤ 400 мс, граф ≤ 800 мс; LCP < 2.5 с; CLS < 0.1 |
| Доступность | WCAG 2.1 AA-базовый уровень: контраст, клавиатура, axe 0 critical/serious |
| Надёжность | `migrate reset` + seed воспроизводимы; повторный сид идемпотентен |
| Безопасность | OWASP Top 10 (применимые пункты), секреты вне git |
| Совместимость | Node ≥ 20, pnpm ≥ 9, Docker; PostgreSQL 17 |
| Сопровождаемость | слои controller/service/repository; общие типы в `packages/shared`; документация синхронна коду |
| Тестируемость | unit ≥ 80% сервисов; каждый API-маршрут happy+error; 8 e2e-сценариев |

## 6. Технические решения (утверждены)

Определены в `docs/spec/03-architecture.md` и `README.md`: монорепо pnpm + Turborepo, Next.js 15, NestJS 11, Prisma 6, PostgreSQL 17, FTS/trgm, React Flow, MapLibre, cookie-сессии, Docker Compose. Отклонения — только через ADR.

## 7. Ограничения и допущения

1. Репозиторий создаётся с нуля; кода для сохранения нет.
2. Доступ к GitHub — через сохранённые credentials; `gh` отсутствует, PR создаётся через веб.
3. Порты: 3000/4000/5433 (5432 занят локальным PostgreSQL на машине разработки).
4. Данные — только реальные, с источниками; выборочная ручная проверка 10%.
5. Один узел развёртывания; без Redis и очередей.

## 8. Этапы и критерии готовности

Этапы 0–11 по `docs/spec/06-delivery-plan.md`. Этап сдан при: зелёном CI, выполненных критериях приёмки, отчёте по шаблону MASTER PROMPT, отсутствии заглушек в пользовательских путях.

## 9. Риски

См. `docs/AUDIT.md` §9. Ключевые: объём работ (с нуля), достоверность данных, отсутствие `gh` для автоматизации PR.
